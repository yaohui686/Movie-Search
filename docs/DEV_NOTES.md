## 一、为什么会闪退（已修）

一共三个原因，叠在一起：

| # | 原因 | 现象 | 修法 |
|---|---|---|---|
| 1 | 双击 `run.py` 时没带参数 | 打印帮助后立刻退出，窗口一闪就没 | 无参数时**自动进入交互模式** |
| 2 | **控制台 UTF-8 与 Python stdin GBK 不一致** | **一输入中文就 `UnicodeDecodeError` 崩掉** | `.cmd` 里加 `PYTHONUTF8=1`，`run.py` 里把 stdin/stdout 一起拉成 UTF-8 |
| 3 | 报错后窗口立刻关闭 | 看不到任何错误信息 | 顶层捕获 + `logs\crash.log` 留痕 + `.cmd` 出错 `pause` |

第 2 条是最隐蔽的：`chcp 65001` 让控制台按 UTF-8 收键盘，但 Python 3.13 默认仍用 locale（GBK）读 stdin，两边对不上，输入中文必然解码失败。所以必须同时设 `PYTHONUTF8=1`。

**现在双击 `影视检索.cmd` 即可，输入中文不会崩。**

如果还崩，看 `logs\crash.log`，里面有完整堆栈。

## 三点二、在线播放

### 为什么不能直接把 m3u8 丢进浏览器

两个问题：

| 问题 | 影响 | 解法 |
|---|---|---|
| **CDN 防盗链** | 多数资源站校验 `Referer`，浏览器直接拉会 403 | 本地起代理，转发时补 `Referer` 和 `UA` |
| **Chrome 不支持原生 HLS** | `<video src="xxx.m3u8">` 在 Chrome 里放不出来 | 播放页用 `hls.js` 解码 |

### 用法

```powershell
python run.py play 流浪地球          # 播第 1 条
python run.py 流浪地球 --play        # 同上
python run.py play 流浪地球 -n 3     # 播第 3 条
```

也可以在交互模式里输入 `p 流浪地球`。

执行后会自动开浏览器，本地代理地址形如：

```
http://127.0.0.1:58707/play?u=https%3A%2F%2F1080p.huyall.com%2Fplay%2Fe311jP9b%2Findex.m3u8
```

### 代理做了三件事

1. **补请求头**：按 m3u8 的域名自动生成 `Referer`，并带上浏览器 UA
2. **改写分片地址**：m3u8 里 50+ 个 `.ts` 分片的相对路径全部转成绝对地址、再包一层 `/proxy?u=`
3. **处理加密 KEY**：`#EXT-X-KEY:URI="key.bin"` 里的密钥地址同样走代理

实测（`tools/e2e_play.py`）：

```
[1] 播放页 200  1887B  hls.js=True
[2] 代理 m3u8 200  application/vnd.apple.mpegurl  114 行  分片 54 个
    首个分片: /proxy?u=https%3A%2F%2Fc.baisiweiting.com...plist0.ts
    分片已改写: ✅
[3] 首分片 200  200 KB  type=video/mp2t
```

## 三点三、下载

### 三种下载方式，挑顺手的用

| 方式 | 命令 | 适合 |
|---|---|---|
| **下载页（最省事）** | `python run.py link 泰坦尼克号` | 自动打开本地下载页，**浏览器点「下载」直接另存为** |
| **迅雷批量** | `python run.py link 泰坦尼克号 --txt --clip` | 直链进剪贴板/txt，迅雷新建任务整批粘贴 |
| 交互模式 | 双击 `影视检索.cmd` → 输入 `link 泰坦尼克号` | 同样打开下载页（`l 片名` / `d 片名` 也行） |
| 命令行自动下 | `python run.py download 泰坦尼克号` | 不开浏览器，直接下到当前目录 |

### 下载页长什么样

`link` 会打印链接清单（终端里也能复制），然后**自动打开本地下载页**（和播放页同一套本地代理）：

- 每条结果一个卡片：片名 / 年份 / 画质 / 集数 / 来源
- 直链 mp4 → 点「**下载**」浏览器直接另存为（代理已补 Referer 过防盗链，
  `Content-Disposition` 强制附件下载，**支持暂停后点继续（断点续传）**）
- 点「**复制**」拿原始直链，粘给迅雷/IDM；顶部「**复制全部直链**」一键批量
- 没有直链只有清单的条目会标注，回终端用 `download` 走拼接
- 回到终端窗口按回车，下载服务随之结束

实测（`/file` 代理端点）：206 断点透传 ✅、中文文件名 `filename*` ✅、
MP4 头校验 ✅、页面直链列表 ✅。

### 下载链接分两档（重要）

资源站 API 里其实藏着两种地址，`link` 会分档标出来：

| 档位 | 长相 | 怎么下 |
|---|---|---|
| **直链文件**（标「有直链」） | `https://dow1.lzidw2025.com/.../泰坦尼克号1997.mp4` | 迅雷 / IDM / **浏览器直接另存为**——就是一个完整 mp4 |
| 播放清单（标「无直链」） | `https://.../index.m3u8` | 不是视频文件；迅雷可试边下边播，稳妥用 `download` 走拼接 |

直链来自接口的 `vod_down_url` 字段：**量子资源给全（每集一个 mp4）**，其余源大多空着——
所以「有没有直链」取决于来源，合并时各源直链会并进同一条结果。
想复查哪些源带直链：`python tools\probe_down.py`。

### link 的完整用法

```powershell
python run.py link 泰坦尼克号                 # 全部结果的链接
python run.py link 泰坦尼克号 -n 1            # 只要第 1 条
python run.py link 狂飙 -e 1-5                # 电视剧选集：1-5 集
python run.py link 狂飙 -e 1-3,7              # 混合选集也行
python run.py link 狂飙 --txt --clip          # 链接写进 txt 并复制进剪贴板
```

`--txt` 产出的 txt 一行一个链接，在迅雷「新建任务」里整批粘贴即可；
`--clip` 直接把同样的内容放进剪贴板（走 PowerShell `Set-Clipboard`）。

实测输出（电影）：

```
[1] 泰坦尼克号 (1997)　4K　2 集　有直链　[暴风资源/最大资源/电影天堂/量子资源/…]
    [直链文件] HD中字　https://dow1.lzidw2025.com/20220321/216_db01adcf/泰坦尼克号1997.mp4
```

剧集（`link 旋风战车队第二季 --txt` 这类）每集一行 mp4 直链，一次可导出几十集。

### download 的路线优先级

| 优先级 | 条件 | 路线 | 产出 |
|---|---|---|---|
| 1 | 结果带直链 mp4 | 整文件流式下载（256KB 分块，断点续传） | `.mp4`，失败留 `.part`，重跑续传 |
| 2 | 有 ffmpeg（`bin\ffmpeg.exe` 或 PATH） | ffmpeg 拉 m3u8 合并 | `.mp4` |
| 3 | 没有 ffmpeg | 纯 Python 拉分片拼接 | `.ts`（VLC/PotPlayer 直接能播） |

选集：`python run.py download 狂飙 -e 3` 或 `-e 1-5`；不加 = 全部直链逐个下。

纯 Python 路线做的四件事：
1. **递归解析播放清单** —— 很多站点是嵌套的：外层主清单 → 内层分片清单，会一层层剥到最里面
2. **8 线程并发拉分片**
3. **按顺序拼接**（顺序错了画面会乱）
4. **处理 `#EXT-X-MAP`**（fMP4 初始化段放最前）

实测：解析到内层 5235 个分片，抽样 12 个共 2.3MB，首字节 `47` = 合法 MPEG-TS。
直链路线另实测：206 断点续传 ✅、半截 `.part` 续传 ✅、不支持 Range 的服务器自动回退全量 ✅。

加密流（`METHOD=AES-128`）会提示需要 ffmpeg。

## 三点四、画质真相（重要）

### 资源站标的「4K」基本是假的

拿《泰坦尼克号》实测，42 条资源全部扫一遍真实分辨率：

| 真实分辨率 | 条数 |
|---|---|
| 1080x608 @ 800kbps | **21 条** |
| 单码率（无分辨率信息） | 17 条 |
| 1280x720 @ 1738~2000kbps | 2 条 |
| 1024x576 @ 2000kbps | 1 条 |
| **2160p（真 4K）** | **0 条** |

**标着「4K」的那条，m3u8 里写的是 `1080x608 @ 800kbps`。**

- `1080x608` 是 2.39:1 宽银幕裁切后的 1080P，实际像素只有 65 万
- `800kbps` 码率偏低，观感接近 720P
- 所以你觉得「像 1080P」——**其实就是 1080P，甚至不到**

### 为什么画质不能调

这些 m3u8 是 master playlist，但**里面只有一个变体**：

```
#EXT-X-STREAM-INF:BANDWIDTH=800000,RESOLUTION=1080x608
1200k/hls/mixed.m3u8
```

只有一路码率，播放器没有别的可选。所以不是播放器的问题，是片源就这一档。

### 查真实画质

```powershell
python run.py info 泰坦尼克号 -l 5
```

```
#   片名                        年份     标签      真实分辨率
------------------------------------------------------------------------------
1   泰坦尼克号                     1997   4K      1080x608@800k
2   泰坦尼克号                     1998   未标注     1280x720@1738k
3   泰坦尼克号2                    2010   未标注     1280x720@2000k
```

「标签」是资源站自己写的，「真实分辨率」是 m3u8 里写死的——**以后以这一列为准**。

### 想要真 4K 怎么办

这 15 个苹果CMS 源站基本都只有 1080P 压制版。真要 4K 只能：

| 途径 | 说明 |
|---|---|
| 专门的高码率资源站 | 极少数站点提供 4K 原盘/Remux，但通常要注册或付费 |
| 网盘分享 | 搜索"4K 原盘/Remux"关键词，多是蓝光压制的 |
| 正版平台 | 腾讯/爱奇艺的 4K 需 SVIP |

**这个工具解决的是"哪家有"，不解决"有多清晰"**——片源质量取决于源站，不由工具决定。

## 三点五、模糊搜索是怎么做的

### 之前的问题

只有「片名打得准」才搜得到。实测四种常见输入全部空手：

| 输入 | 类型 | 修复前 |
|---|---|---|
| `流浪地求` | 错别字 | ❌ 无结果 |
| `流浪地球2 2019` | 带年份 | ❌ 无结果 |
| `流浪地球 电影` | 带噪声词 | ❌ 无结果 |
| `liulangdiqiu` | 拼音 | ❌ 无结果 |
| `The Wandering Earth` | 英文名 | ❌ 无结果 |

原因是双重的：源站按 `wd=` 做子串匹配（对错别字无能为力），本地又用 0.72 相似度硬筛。

### 现在的四层机制

**第 1 层：查询清洗**（`filmsearch/fuzzy.py`）

自动剥掉不改变作品身份的噪声：年份、括号内容、`完整版`/`国语版`/`高清`/`1080P`/`电影` 等。

```
流浪地球2 2019  →  流浪地球2
流浪地球（国语版）→  流浪地球
```

**第 2 层：多路召回**

同一部片可能被用户写成多种样子，所以生成多个变体**并发**去查所有源，结果合并去重：

```
["流浪地球2 2019", "流浪地球2", "流浪"]
```

**第 3 层：LCS 错别字容忍**（`matcher.fuzzy_ratio`）

用最长公共子序列算覆盖率，而不是纯字符串相似度：

```
流浪地求  vs  流浪地球   → LCS=3，覆盖率 75%  →  得分 0.90  ✅
```

三条保护规则防止误伤：

| 规则 | 作用 |
|---|---|
| 查询 < 3 字不做 LCS 加成 | 防止「地球」匹配一切 |
| 存在包含关系时不加成 | 防止「流浪地球」和「流浪地球2」混为一谈 |
| 覆盖率 < 60% 不给分 | 防止沾边就算 |

**第 4 层：自适应宽召回**

第一轮最好的结果如果连 0.95 都不到（说明匹配不确定），自动用前两字再捞一轮：

```
匹配不够确定，宽召回「流浪」补一轮…
```

只补召回、不放松打分——宽召回捞回来的仍然要按原词评分。

### 修复后实测

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `流浪地求` | 0 条 | **6 条**（流浪地球、流浪地球2…） |
| `流浪地球2 2019` | 0 条 | **5 条**（两个都命中，1.0 分） |
| `流浪地球 电影` | 0 条 | **3 条** |
| `liulangdiqiu` | 0 条 | ❌ 仍不支持（需拼音库） |
| `The Wandering Earth` | 0 条 | ❌ 仍不支持（源站无英文名） |

### 仍不支持的两类

| 类型 | 原因 | 解法 |
|---|---|---|
| **拼音输入** | 需要汉字→拼音词典 | `pip install pypinyin` 后加一路召回，约 20 行 |
| **英文名** | 苹果CMS 站点不存英文标题 | 只能靠豆瓣别名反查，覆盖有限 |

**建议**：拼音和英文名这两种，直接搜中文名最快。

### 性能优化（15 个源还能 3–6 秒出结果）

| 手段 | 效果 |
|---|---|
| 并发查询（16 线程） | 15 个源并行，不串行 |
| **整体截止 6 秒** | 慢源超时直接丢下，不拖累整体 |
| 分阶段收敛 | 先打原词，不够再打清洗词，最后宽召回（限前 6 源） |
| 批量检索不重试 | 单源失败无所谓，重试只会让耗时翻倍 |

关键坑：`with ThreadPoolExecutor(...)` 退出时会 `shutdown(wait=True)`，**等所有慢线程结束**，把截止时间完全废掉。必须改成 `shutdown(wait=False, cancel_futures=True)`。

## 六、匹配逻辑（决定好不好用的核心）

资源站的标题五花八门：「流浪地球」「流浪地球2」「流浪地球[电影解说]」「流浪地球2：再次冒险」……必须打分排序。

`matcher.py` 三步：

1. **归一化**：去《》空格标点、全半角统一、转小写
2. **包含惩罚**：`繁花` vs `双面繁花`、`流浪地球` vs `流浪地球2` 这类"包含但不同片"的关系按字符差降权（0.15/字），避免把无关片当命中
3. **年份加权**：同年 +0.15，差 1 年 +0.05，差 2 年以上 ×0.75

阈值 0.72，`--threshold` 可调。

**实测效果**：

| 查询 | 修复前 | 修复后 |
|---|---|---|
| 流浪地球 | 混入地球防卫军、环太平洋、星际宝贝等 19 条噪声 | 只剩「流浪地球」「流浪地球2」 |
| 繁花 | 混入双面繁花、那树繁花 | 只剩「繁花」 |
| 狂飙 | 混入越野狂飙、弹速狂飙、怒斩狂飙 | 只剩「狂飙」 |

## 七、已知限制

| 限制 | 说明 |
|---|---|
| 部分结果指向"分享页" | 已做修正：优先挑线路里的 m3u8 直链，没有才退回第一集地址 |
| **下载直链只有部分源给** | `vod_down_url` 实测仅量子资源全量提供，其余源只有 m3u8 清单，`link` 会分档标注 |
| 番剧/短剧较多 | 资源站收录杂，靠匹配分过滤 |
| 冷门片可能搜不到本体 | 例：《旋风战车队》这 15 个源未收录，只能匹配到「旋风×第二季」这类沾边结果 |
| 源站可能失效 | 资源站域名经常变，`cfg/app.json` 里改 `api` 即可换源 |
| 不解决"能不能播" | m3u8 有效性和 CDN 可用性要播放器验证 |
